# Bounds check caught: null pt partition at index 31 in LTdotProductPtBatch

Date: 2026-09-09. GPU: Quadro GV100 32 GiB. Commit: 081261a.

## The diagnostic

The new bounds check in `LimbPartitionBatch.cu` caught the crash precisely:

```
FIDESlib: LTdotProductPtBatch got a null pt partition at index 31
```

This happens during `EvalBootstrap` in `test_stage4_bootstrap.py` (the GPU
bootstrap test), which uses:
- log_n=13, depth=25, dnum=3, levelBudget=(3,3), 4096 slots
- 46 rotation keys, 15 truncated, 0 grown at runtime
- bootstrap key level plan: 32 of 45 keys truncated, by level: 24x32

## What it means

The `pt` array (plaintext diagonals for the CoeffsToSlots linear transform)
has a **null pointer at index 31**. The kernel would have dereferenced this
null pointer, causing the illegal memory access we saw in previous runs.

### This is NOT a limb count mismatch

The error is "null pt partition" — the plaintext partition itself is missing,
not just too few limbs. Index 31 of the pt array was never allocated or was
not populated.

### Likely cause

The CoeffsToSlots linear transform precomputes plaintext diagonals. With
levelBudget=(3,3) and 4096 slots, the CtS transform has multiple layers. The
plaintext at index 31 is either:
1. Not being generated by the precomputation (a gap in the diagonal indexing)
2. Being generated but at a different level than expected, so it's not found
3. Being freed/garbage-collected before the kernel runs

### This reproduces in a small test

The crash happens in `test_stage4_bootstrap.py` — a simple bootstrap test
with log_n=13 (4096 slots), not the full THOR benchmark. This means the bug
is in the bootstrap itself, not in THOR's stage wiring.

## Also: compile error in Context.cu (recurring)

`KeySwitchingKey` has `const` members (via `CudaNvtxRange`), so copy-assignment
is deleted. The remote's `Context.cu` line 658:
```cpp
existing->second = std::move(ksk);
```
fails to compile. I fixed it locally with erase+emplace:
```cpp
if (replace) {
    const int idx = existing->first;
    keys.erase(existing);
    keys.emplace(idx, std::move(ksk));
}
```
This needs to be fixed on the remote side too, or `git reset --hard` keeps
overwriting my fix.
