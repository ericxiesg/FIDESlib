## 2. 【要改】第 4 节的"周期 2048"是分组样本数造成的假象

按 `slot % k` 分组时，每组有 `32768/k` 个样本，组均值的标准误按 `1/sqrt(n)` 缩小，
而组数又变多、极差还会跟着涨。**所以即使误差完全没有结构，spread 也必然随 k 单调上升。**

| 分组 | 每组样本数 | 组数 |
|---|---:|---:|
| `slot%16` | 2048 | 16 |
| `slot%128` | 256 | 128 |
| `slot%2048` | 16 | 2048 |

拿一个**纯 i.i.d. 高斯**（σ 由你的 p50 反推得 0.0155）模拟同样的分组，跑三次：

```
  i.i.d. 模拟 spread: %16=0.000699  %128=0.00281  %2048=0.0151   比值 1 : 4.0 : 22
  i.i.d. 模拟 spread: %16=0.000721  %128=0.00275  %2048=0.0159   比值 1 : 3.8 : 22
  i.i.d. 模拟 spread: %16=0.000674  %128=0.00334  %2048=0.0152   比值 1 : 5.0 : 23
  你的实测   spread: %16=0.000655  %128=0.00291  %2048=0.0151   比值 1 : 4.4 : 23
```

**每一个实测值都落在纯噪声模拟的范围内，连绝对值都对得上。**

再两条独立佐证。半正态分布满足 `p50 = 0.6745σ`、`p99 = 2.576σ`：

```
由 p50 = 1.044e-2 反推 sigma = 0.01548
由 p99 = 3.959e-2 反推 sigma = 0.01537      <- 两个独立统计量给出同一个 sigma
32768 个样本的 |N| 极值约 4.1 sigma = 0.0635，实测 max = 0.0619
```

**三个统计量（p50、p99、max）用同一个 σ 全部对上。** 这是一个干净的高斯，不是结构性错误。

### 后果：2048 和 THOR 的 group_size 无关

这次测的是**裸 bootstrap**，消息是零密文和全 1.0，THOR 的
`slot = group*2048 + token*16 + block` 这个 layout 根本没参与。数字撞上是巧合。

**所以"周期 2048 指出是 CtS/StC 的哪一层"这条线索不成立**，
你第 6 节的下一步 #1（找哪一层的对角线数和 2048 有关）会是一趟空跑。
先别去。

## 3. 一个三行的实验，可以把我的统计论证变成定论

统计学论证再干净也还是论证。下面这个是直接测：

```python
ct = engine.encrypt(np.zeros(engine.slots, dtype=complex))
e1 = np.real(engine.decrypt(engine.bootstrap(ct)))
e2 = np.real(engine.decrypt(engine.bootstrap(ct)))     # 同一个输入，再来一次
print("相关系数:", np.corrcoef(e1, e2)[0, 1])
print("差的量级:", np.abs(e1 - e2).max(), " vs 各自的量级:", np.abs(e1).max())
```

* **相关系数 ≈ 0** → 每次运行都不同 ⟹ 是**随机噪声**，我的读法成立；
* **相关系数 ≈ 1，差 ≈ 0** → 两次完全一样 ⟹ 是**确定性误差**（某个常数表、某个明文编错），
  那反而好办得多，因为可以直接把它减出来看长什么样。

**这一个数决定后面整条路怎么走**，请先跑它。

## 4. 如果是噪声，它有多大

σ = 0.0154 是**消息域**的。换到系数域是 `0.0154 × Delta = 0.0154 × 2^50 = 2^44.1`。

而 ModRaise 之后密文携带的是 `m + q0*I`，量级到 `K*q0`，约 `2^59.6`。
所以 **CtS/StC 只保住了这个大数的约 15 个 bit**。

作为对照：我们流水线的其余部分（q/k/v/scores，每层几千次旋转和明文乘）
MAE 是 **1e-7**。也就是说 bootstrap 的噪声比其余部分差 **五个数量级以上**。
这个落差太大，不像是"参数选得不够好"，更像是某一处算错了。

### 所以第二个实验：key switch 本身健不健康

CtS/StC 主要就是旋转加明文乘。单独测一次旋转：

```python
x  = np.full(engine.slots, 0.25)
ct = engine.encrypt(x)
r  = engine.rotate(ct, 1)
print("一次旋转的误差:", np.abs(np.real(engine.decrypt(r)) - np.roll(x, -1)).max())
```

* **~1e-13** → key switch 健康，噪声出在 bootstrap 自己的算术里
  （对角线的编码精度、Chebyshev 系数表、double-angle）；
* **~1e-3** → key switch 本身就坏了，那它解释的就不止 bootstrap——
  我们每层有 4000–8000 次旋转。

不过我预计是前者：q/k/v 的 1e-7 是在几百次旋转之后测到的，
反推单次旋转的噪声应该远小于 1e-9。这个实验主要是**把它正式排除掉**。

## 5. 关于你的下一步 #2（换 level budget）

先别换。理由有两条：

1. **它不是精度旋钮**。这一点 `report/part21-review-20260915.md` 里核过：
   EasyFHE 的模型里 level budget 只出现在深度公式 `approx_depth + budget[0] + budget[1]`，
   **不接触任何一个精度相关常量**。四个代码库全是 (3,3)。
2. **代价确定、收益不确定**。同深度下 (4,4) 比 (3,3) 贵 1.38 GiB（depth 37，我们自己的
   `budget.estimate` 实测），还要再多付 2 层 bootstrap 深度——而深度现在是卡死的。

如果第 3 节的相关系数说是确定性误差，那和 budget 更没关系了。
