## 0. 先说更正

`efc57a3` 里我写：

> "共轭是 Galois 自同构 `slot j -> slot -j`，`slot 0` 是它唯一的不动点。"

**这是错的。** CKKS 的共轭**在槽内原地作用**：`v_j -> conj(v_j)`，不置换槽。
本仓 `clear.py:296` 的实现就是 `np.conj(ct.slots)`，设备侧语义相同
（`add(ct, conj(ct))` 得到逐槽的 `2·Re`，`stage_07` 的 docstring 也是这么写的）。

作为置换它是**恒等**——**固定所有槽，一个也不特殊**。所以那条理由不成立。

（补一句以免又跑偏：在**系数**域上，`x -> x^{-1}` 确实把系数 0 映到自己，
那在 kernel 里是个真的特例分支。但系数 0 对**每个**槽的贡献都是 ζ⁰=1，
它错了是给所有槽加同一个偏移，**不会只坏一个槽**。所以这条也救不回来。）

**`efc57a3` 的结论（"嫌疑是 conjugate"）现在只剩"位置相关"这一条弱证据，不是机制。**
测试我留着——它便宜，而且确实测了一个位于两个症状正上游的算子——
但已经把 docstring 里那句错的删掉了。**请不要按"不动点"这个说法去找。**

## 3. 不再猜算子，改二分

我上一条是在猜。既然候选只剩"某个算子"，那就**定位**，别猜。

### 3.1 已改：`magnitude_probe` 现在**永远**报 `worst at`

之前 `worst at` 只在 `<0` 或 `>1` 触发时才打印。这正好错过了要的那一步：
`inv_iter01_b` **在范围内**，所以从不打印位置，而它恰恰是"slot 0 什么时候开始变坏"
的第一个观测点。等到 `07d` 打印位置时，坏已经成了。

现在每个探针都带三个最大槽的 index。三个整数，不花钱。

### 3.2 要的东西：一次跑，`inv_iter01_b` 到 `iter04_b` 的 `worst at`

```bash
THORFHE_DEBUG=1 ... --inverse-lift 3 --check-ranges warn
```

然后把 `07.inv_iter01_a/_b` 到 `iter04_a/_b` 的**完整行**贴出来（现在带位置了）。

- **`iter01_b` 的最大槽已经是 0** → 坏在迭代**之前或第一步**：
  即 `bootstrap` / `PADDING_FLOOR` 的加法 / 第一次 `subtract` + `_times`；
- **`iter01` 正常、到 `iter02`/`03` 才变成 0** → 坏在迭代**内部**，
  而每轮只有四个算子：`subtract(scalar, ct)`、`_times`（multiply+relinearize+rescale）、
  `add(ct, conjugate(ct))`、`multiply(ct, int)`。**一轮之内就能钉死是哪个。**

这比我继续猜快，也比跑 Meta-BTS 有把握。

### 3.3 顺手拿到了健康参考——而且它指出了新东西

改完立刻在本机跑了一遍，`07` 这条链的位置是这样的：

```
07c.denominator    max +0.3036    worst at 17075(%3),12979(%3),4787(%3)
07.inv_iter01_b    max +0.274     worst at 31370(%10),29322(%10),27274(%10)
07.inv_iter02_b    max +0.02574   worst at 6709(%5),12853(%5),31285(%5)

07d                max +0.04903   worst at 6580(%4),22964(%4),12724(%4)
```

**健康的时候最大槽是游走的**：%3 → %10 → %5 → %4 → %6，**没有一步落在 slot 0**。

而且注意最后一行。`07d` 的最大槽是 **6580 / 22964 / 12724**——
正是 §2 里那六个**分母最小**的槽（`%2048=436` 那一族，值 0.026431）。

> **健康的 `07d`，最大值出现在分母最小的地方。这是算术上应该的：分母最小 → 逆元最大。**
>
> **设备的 `07d`，最大值在 slot 0——而 slot 0 的分母排第 688。**
> **所以设备的 `07d` 不只是数值错了，它的最大值出现在了错误的位置。**

这是一条独立于幅度的证据：就算不看 5.8e+05 这个数，**位置本身就已经不对**。

## 4. 关于"σ 减半反正能修"

你 §4 最后写："Meta-BTS 仍然是最直接的修法——不管原因是什么，σ 减半就行。"

**如果是算子 bug，这句不成立。** 一个确定性的缺陷不会因为噪声减半而消失——
它会从"每次坏 1 个槽"变成"每次还是坏 1 个槽"。而我们会得到一个更贵的 bootstrap、
一个仍然 0% 的 accuracy，以及一条被掩盖的线索。

**证据也指向算子而不是噪声**：噪声每次抽样都不同，而 `07d` 的坏槽**三次跑都在 slot 0**。
随机的原因产生不了固定的结果。

Meta-BTS 该做，但**在 §3.2 之后**——它是精度的修法，现在缺的是"是不是精度问题"的答案。
