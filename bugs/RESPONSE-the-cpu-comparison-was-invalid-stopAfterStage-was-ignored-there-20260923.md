## 1. CPU 分支忽略了 `stopAfterStage`

`api/CryptoContext.cpp:1762`（修改前）：

```cpp
if (this->devices.empty()) {
    auto ct = context->EvalBootstrap(ctImpl, numIterations, precision);   // ← 没有 stopAfterStage
    ...
}
```

OpenFHE 的 `EvalBootstrap` 没有这个参数，所以 CPU 分支**把它丢掉，跑完整个 bootstrap**。

> **所以「GPU stage 2」对比的是「CPU 完整刷新后的结果」。两个不同的计算。**
> **CPU 没有零槽，是因为它交出的是一个刷新完成的密文，不是 CtS 的中间态。**

### 1.1 这是我的错，而且是我自己批评过的那种错

我在 header 里写了「GPU path only」，**但代码是静默忽略，不是拒绝**。
而我在 Part21 的复核里批评过一模一样的事——
GPU 路径丢掉 `numIterations`/`precision`，当时我写的是
**「一个被静默忽略的参数比没有这个参数更糟」**。然后我自己造了一个。

**已修**：CPU 分支现在在 `stopAfterStage != -1` 时抛异常，说明为什么。

## 2. k/56 和「零槽」要重新理解

你报的所有非异常值都是 **1/56 的整数倍**：

```
1/56 = 0.017857    2/56 = 0.035714    3/56 = 0.053571    5/56 = 0.089286    6/56 = 0.107143
```

也就是说，**整个 32768 维向量只取了大约 7 个不同的值**。

而输入是 `uniform(0.0814, 0.9812)` 的稠密随机向量——**它的编码不会是一个 7 级信号**。

> **这不是「结构性量化」，这是「在一个未定义的中间 scale 上解码」的样子。**

`bootstrap_stage` 的文档里就写着：
「its level, scale and slot layout are mid-flight」「not a usable refreshed ciphertext」。
**所以 stage 2 输出的绝对值不可解释，能用的只有比值。**

于是：
- **「3211 个槽 < 1e-6」= 3211 个槽量化到了 0**，在一个粗到只有 7 级的网格上，这很正常；
- **k/56 不是证据**，是 scale 未知的副作用；
- **比值仍然有效**：slot0/p50 = 0.001 是无量纲的，§2 的结论不受影响。

### 2.1 你那条「非确定性」才是最有意思的

> 两次跑，slot 0 读到 0.01793 和 7.39e-05，而中位数两次都是 0.05357。

在 1/56 的网格上，**0.01793 ≈ 1/56，7.39e-05 ≈ 0**。
**slot 0 在两次跑之间跨过了一格。** 其它槽（9891、19782）稳定在 1/56。

> **所以 slot 0 的真值就坐在量化边界上，噪声决定它落哪边。**
> 这比「slot 0 是 0」信息量大得多：它不是被写坏了，是**本来就接近零**。

## 3. slot 20170 在 CtS 正常，这一条你标了但没展开

`20170` 在 CtS 是 6/56，完全正常；但它在最后的乘法里是 worst-5 之一。

**所以 CtS 的异常槽集合（0、16687）和乘法的坏槽集合（0、1、9891、19782、20170）不一样。**
交集只有 slot 0。

这意味着**至少有两件事在发生**，不是一条因果链：
CtS 让 slot 0 塌掉是一件事；乘法在 20170 上出错是另一件。
**把它们当成同一个根因去找，会两头都对不上。**

## 4. 下一步：先把参照系修对

在 CPU 侧做同样的 stage 比较，**现在会抛异常**——这是对的，因为那个比较本来就不成立。

要有一个合法的参照，只有两条路：

1. **在 CPU 侧实现 `stopAfterStage`**（OpenFHE 的 bootstrap 是分步的，可以在
   `EvalCoeffsToSlots` 之后取出来）——工作量不小；
2. **放弃跨后端比较，改用 GPU 内部的不变量**：
   比如同一个输入跑两次，比较 stage 2 输出的**逐槽差**——
   §2.1 说明 slot 0 是不稳定的，那么「哪些槽在重复跑之间不稳定」本身就是一张图，
   **不需要 CPU 参照，也不受 scale 影响**。

**建议走第 2 条**，它便宜、不需要新代码（跑两次 stage 2，相减），
而且直接回答「slot 0 的不稳定是孤立的还是一群」。
