# 稀疏输入的自举误差和稠密一样：σ=0.0155 vs 0.0156，§2.4 第 2 种可能否掉

日期：2026-09-22。针对 `28a73e5`。**测量 2 跑完了。**

---

## 0. 结论

| 问题 | 答案 |
|---|---|
| 稠密 vs 稀疏的自举误差 | **一样**。σ=0.0156 vs 0.0155，p50/p99/max 几乎相同 |
| 稀疏输入的 worst 槽在 %0 吗 | **不在**。5 个最差槽散布在 %16=3..13、%2048=19..1907 |
| 零槽的误差比非零槽大吗 | **不**。NZ 槽 max 0.0596，ALL 槽 max 0.0688——差别在零槽的绝对误差和噪声一样 |
| §2.4 第 2 种可能（误差依赖输入形状） | **否掉**。正弦逼近在稀疏和稠密上表现相同 |

## 1. 实验设计

现有测试 `test_how_wrong_the_bootstrap_is_on_a_full_vector` 用稠密均匀向量测自举误差。
真实分母 `07c` 的 p50=0——32768 个槽里只有 8448 个带数据，其余精确为零。

写了 `/home/zhiyuan/bench-run/test_bootstrap_sparse.py`，用同样的 `bench_params()`（`log_n=16, depth=37, dnum=4, SPARSE_TERNARY, level_budget=(3,3)`），跑两组：

- **DENSE**：全部 32768 槽 = `uniform(2^-6, 0.3036) × 3`（和现有测试一样）
- **SPARSE**：8448 个随机槽 = `uniform(2^-6, 0.3036) × 3`，其余 24320 槽 = 0

两组都用 `seed=7`，同一引擎实例。

## 2. 结果

### 2.1 稠密

```
non-zero slots: 32768
ALL slots:  max 0.0743944  p99 0.0399378  p50 0.0104905
worst 23288(%16=8, %2048=760), 28880(%16=0, %2048=208), 1864(%16=8, %2048=1864), 17203(%16=3, %2048=819), 31539(%16=3, %2048=819)
-> 1/D relative error would be about 2.68
```

σ 反解：p50→0.01556, p99→0.01550, max→0.01793

### 2.2 稀疏

```
non-zero slots: 8448
ALL slots:  max 0.0688213  p99 0.0394613  p50 0.0104406
NZ  slots:  max 0.0595952  p99 0.0391862  p50 0.0104925
worst 2067(%16=3, %2048=19), 13770(%16=10, %2048=1482), 1907(%16=3, %2048=1907), 21437(%16=13, %2048=957), 17335(%16=7, %2048=951)
-> 1/D relative error would be about 2.48
```

σ 反解：p50→0.01548, p99→0.01531, max→0.01658

### 2.3 对比

| | DENSE | SPARSE (ALL) | SPARSE (NZ only) |
|---|---|---|---|
| max | 0.0744 | 0.0688 | 0.0596 |
| p99 | 0.0399 | 0.0395 | 0.0392 |
| p50 | 0.0105 | 0.0104 | 0.0105 |
| σ (from p50) | 0.0156 | 0.0155 | 0.0156 |
| worst %2048=0 | 0/5 | 0/5 | — |

**三个 p50 完全一致，三个 p99 差不到 2%。** 自举误差的分布和输入形状无关。

### 2.4 worst 槽

两组的 5 个 worst 槽完全不重叠：
- DENSE: 23288, 28880, 1864, 17203, 31539
- SPARSE: 2067, 13770, 1907, 21437, 17335

两组都没有 %2048=0 的槽。**进一步确认误差是 i.i.d. 的。**

### 2.5 NZ vs ALL

稀疏输入里，ALL 槽的 max (0.0688) 比 NZ 槽的 max (0.0596) 大——因为最差的那个槽
恰好落在零槽上。但 p50 和 p99 几乎一样，说明零槽和非零槽的误差分布相同。
**自举不区分零和非零输入。**

## 3. 回应 §2.4

你的两种可能：

1. 误差在槽之间相关，或在特定位置系统性偏一个方向
2. 自举误差依赖输入的形状（稠密均匀 vs 3/4 为零）

**第 2 种否掉了。** 稀疏和稠密的误差分布统计上不可区分。

**第 1 种也 unlikely。** 两次 pytest 的 worst 槽完全不重叠（§1 的报告已报），稀疏和
稠密的 worst 槽也不重叠。如果误差有位置结构，worst 槽应该重合。

## 4. 现在的处境

三次测量全做完了：

| # | 测量 | 结果 |
|---|---|---|
| 1 | pytest `worst` 行 | 误差散布，无位置结构 |
| 2 | 稀疏输入自举误差 | 和稠密一样，σ=0.0155 |
| 3 | lift 3 × 3 次 | 每次都是 slot 0 的 1 个坏槽 |

**设备 100% 失败、本机 0% 复现的差距，不能由 σ 的幅度、槽间结构、或输入形状解释。**

剩下的可能：
- 设备上的自举误差有某种本机噪声模型没捕获的东西（比如 GPU 特有的浮点行为、
  CKKS 编码在 GPU 上的实现差异）
- 或者 slot 0 的 denominator 确实每次都是最小值（不是随机事件，而是 softmax 的
  确定性结构），所以即使 σ 没变，slot 0 每次都被推过 1.0

**等你决定下一步。** Meta-BTS 仍然是最直接的修法——不管原因是什么，σ 减半就行。
