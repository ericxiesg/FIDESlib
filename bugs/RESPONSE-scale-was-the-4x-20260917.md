## 2. 为什么我们一直对不上

你的式子是 `4 * q.k * scale`，scale = 1/64：

```
4 * q.k * (1/64)  =  q.k / 16
```

而修正后的流水线是 `1 * q.k * scale`，scale = 1/16：

```
1 * q.k * (1/16)  =  q.k / 16     <- 同一个数
```

**你用一个错误的推导（4×）配一个错误的常数（1/64），得到了正确的答案。**
我用正确的推导（1×）配那个错误的常数，得到了错误的答案，然后拿它去质疑你的测量。

所以先前那几轮里，**你的数一直描述的是一条温度正确的流水线该给的值，
我的数描述的是我们实际有的那条坏的**。

---

## 3. 它是怎么错的

`layer.py` 的注释算的是"q 和 k 各 2×、stage 06 的掩码贡献 ½、stage 07 再加倍 = 4×"。

**但加倍的只有偏置**：QKV 阶段产出 `x @ W.T + 2b`，不是 `2(x @ W.T + b)`
（`test_qkv_computes_xw_plus_bias` 写明了，注释里也写了原因——
`encode_weight` 把权重减半来换 `y + conj(y)` 的实数化，而偏置没有跟着减半）。

`2b` 很容易被读成"整个值 2×"。实际 stage 06 精确装乘积（比值 1.0000），
所以 `he_softmax` 看到 `2 * q.k * scale`，要等于 BERT 的 `q.k / sqrt(64)` 就需要 **1/16**。

端到端对着 BERT 自己的 softmax（真实 checkpoint）：

```
scale = 1/64:  对 BERT softmax 的 max 误差 0.9082   <- 本该接近 1 的概率出来 0.09
scale = 1/16:  对 BERT softmax 的 max 误差 0.0023
```

---

## 4. 这独立解释了标定问题

温度高 4 倍 → 分布更平 → 每个 exp 更小 → 它们的和更小。

这正是你测到的：**分母 p50 = 7.03e-5，比 `inv_epsilon` 4.88e-4 小 7 倍**；
以及 `07a.refreshed_scores` 的 [-10.3, 12.4] 只占 NARROW 窗口 [-27.2, 21.7] 的中段。

**这一条和 bootstrap 精度无关，现在就能验证。**
