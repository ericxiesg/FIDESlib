# 更正：窗口外的多项式**不是起飞，是衰减**；`07b/07c` 的负槽是噪声不是发散

## 0. 两处更正

### 更正 1：我说"出了窗口 degree-15 多项式不是变差，是起飞"——**错了**

我没量就写了。量了之后是**单调衰减**，不是发散：

| u = (score−shift)/32 | score | fit / exp(8u) | 经过 softmax 两次平方后 |
|---|---|---|---|
| 0.8654 | 12.43（本机 max） | 1.0000 | 0.9999 |
| 1.1559 | 21.73（窗口上界） | 0.9953 | 0.9812 |
| **1.6488** | **37.50（设备 max）** | **0.8552** | **0.5348** |
| 2.0000 | 48.74 | 0.5891 | 0.1204 |
| 2.5000 | 64.74 | 0.2202 | 0.0024 |

EXP1 实际能跟住 `exp(8u)` 到 1e-3 的区间是 **u ∈ [-0.5956, 1.0388]**。

所以设备 max 那个槽上，指数项**偏低 46%**（两次平方之后）。
是个真实且不小的误差，**但它不会自己变成 5.7e5**。

### 更正 2：我说"`07b` 有 86546 个负槽，而指数不可能为负"——**误导**

我漏看了量级。那些槽是 **−1.412e−09**，`07c` 是 **−1.058e−09**。
**这是被 mask 掉的槽上的噪声，不是多项式发散。** 完全正常。

（EXP1 确实会变负，但只在 score < −41 的地方，而设备的 min 是 −16.05，够不着。）

## 2. 所以现在该查什么

**还是 `07a0`，但问题换了个问法。**

不再是"窗口外多项式炸了"，而是：**为什么设备的分数是本机的 3 倍？**
`scores`（stage 06）比对是准的（relRMSE 2.874e-07），中间只隔着 score refresh 的那次 bootstrap。

```
本机 07a0.score_refresh_input  min -0.3199  max +0.3807
本机 07a.refreshed_scores      min -10.41   max +12.43     （= 0.3807 × 2 × 16 ✓）
```

- **设备 `07a0` ≈ 0.38** → bootstrap 把它放大了 3 倍 → 查 bootstrap
- **设备 `07a0` ≈ 1.17** → 进 bootstrap 前就大了 → 查 stage 06 的打包（注意：per-stage 的
  `scores` 只比对**承载槽**，padding 槽再大也看不见，而探针的 max 是**全槽**的）

第二条我现在觉得更可能，就是因为这个"承载槽 vs 全槽"的差别。

`--score-refresh-scale 2` 照跑，它独立于这条线。
