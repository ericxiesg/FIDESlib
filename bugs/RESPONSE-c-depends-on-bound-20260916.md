# 那堵 66 bit 的墙是把 C 按住造成的。用你自己的数据外推，59/60 能到 21 bit

日期：2026-09-16。针对 `61b9406`。

---

## 1. 先认下来：我的 1.40 bit/bit 是错的

你用第三个点做的干净比较是对的：

```
sb=50 fmb=55 (q0/Delta=32): 11.0 bit
sb=55 fmb=60 (q0/Delta=32): 16.1 bit
slope = 5.1 / 5 = 1.02 bit/bit
```

**保持 `q0/Delta` 不变时，斜率就是 1.0。** 我先前那个 1.40 是从
`sb=50→52`（`fmb` 不变，所以 `q0/Delta` 从 32 掉到 8）算的，
**把 Delta 的效应和界的效应混在了一起。** 你指出得对，我接受。

---

## 2. 但外推到 22 bit 那一步，把 C 按住了

你在报告里自己写了：

> sb=52（q0/Delta=8）给出 C ≈ 2^41.5，更小——**C 本身依赖 q0/Delta。**

然后外推时用的是：

```
precision = log2(q0) - log2(C) = log2(q0) - 44
For 22 bits: log2(q0) = 66
```

**那个 44 是 `q0/Delta = 32` 下的 C。** 而 EasyFHE 的配置是 `q0/Delta = 2`，
按你自己的观察，那里的 C 会小得多。

### 用你自己的三个点拟合

```
q0/Delta = 32:  C = 2^44.01   (sb=50 fmb=55)
q0/Delta = 32:  C = 2^43.86   (sb=55 fmb=60)   <- 同界，C 一致，确认 C 只依赖界
q0/Delta =  8:  C = 2^41.45   (sb=52 fmb=55)

log2(C) 对 log2(q0/Delta) 的斜率 = (44.0 - 41.5) / (5 - 3) = 1.28
```

外推到 `q0/Delta = 2`（EasyFHE）：

```
C ≈ 2^38.9
绝对误差 = C / Delta = 2^38.9 / 2^59 = 8.8e-7
相对界的精度 = log2(q0) - log2(C) = 60 - 38.9 = 21.1 bit
```

**21 bit，`first_mod_bits = 60`，在 64 位以内。** 那堵 66 bit 的墙不存在。

---

## 3. 而且这里混了两个量

你外推的是"**相对界的 bit 数**"。但 `he_inv` 需要的不是那个，是**绝对误差**
和分母的比值：

| 配置 | 绝对误差 | `inv_epsilon = 4.88e-4` 的百分比 |
|---|---:|---:|
| sb=50 fmb=55（现在） | 1.57e-2 | **3200%** |
| sb=55 fmb=60（你建议的第 4 步） | 4.44e-4 | **91%** |
| **sb=59 fmb=60（EasyFHE）** | **8.8e-7**（外推） | **0.18%** |

**你建议的 sb=55/fmb=60 是个半步：误差是分母的 91%，等于没有。**
Goldschmidt 拿到的仍然是"分母 ± 分母"。

而 59/60 是 0.18%——**这才是能用的。**

## 4. 这是外推，请用一次实测钉死

上面的 C 斜率是**两个点**拟合的（界 32 和 8），再外推一个 4 倍到界 2。
两点定不了幂律，和你上轮指出我的问题一样。

**请直接测 EasyFHE 那个配置**：

```
scaling_bits = 59, first_mod_bits = 60, depth 不变
```

测 `{1.0, 10.0}` 这类小值的绝对误差（**不要用 2.0/-3.0 以外的大值**，
因为 `q0/Delta = 2` 时界只有 2，大值会绕圈，那是 Bug 2 不是 Bug 1）。

* 误差 ≈ 1e-6 量级 → 外推成立，**Bug 1 的修法确定是迁到 59/60**；
* 误差远大于 1e-6 → 我的外推错了，那再回来找。

`sb=55` 已经证明只改 `scaling_bits` 不会 OOM，59 只多 4 bit。
