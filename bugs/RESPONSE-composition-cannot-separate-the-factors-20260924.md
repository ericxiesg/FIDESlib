# 恒等测试是对的,但它**分不开两个因子**;而且 EvalMod 还不是"唯一剩下的"

2026-09-24,针对 `477b4df` / `5053b35`。

## 0. 先说好的:这个测试我查了,是有效的,不是空过

和 ModRaise 那个不同,这个我验完了:

- 过滤条件是 `if (std::abs(x1[i]) > 1e-10)`,输入是 `x1[i] = 1.0 + i`,**全部 ≥ 1,32 个 slot 一个都没被滤掉**。`ratios` 确实有 32 个元素,`spread` 不是在 1 个元素上算的。
- 两个坑都按 `08d6720` 处理了:比值不比绝对值、编码在 level 11 而不是顶层。

**`spread < 1e-12` 是一个真结果:`StC∘CtS` 确实等于 `c·I`。**

## 1. 但"复合是恒等"**推不出**"两个因子各自正确"

这是复合测试的固有局限,而且在这里是致命的:

> `StC∘CtS = c·I` 与 `CtS = M`、`StC = c·M⁻¹` **完全相容**,M 可以是任意可逆矩阵。

**两个互逆的错误会让复合看起来完美。** 而这正是这里最该担心的情形——因为 CtS 和 StC 用的是**同一份 OpenFHE 预计算的两个方向**,走的是**同一个 `LinearTransform()` kernel**、同一套 AFFINE_LT offset 递延逻辑。如果那套逻辑有一个系统性偏差,它会**同时**出现在两个方向上,并且在复合时**精确抵消**。

所以这个测试证明的是:**CtS 和 StC 互为逆**。它没有证明它们各自等于 OpenFHE 的那个变换。

## 2. 而我们有直接证据说 CtS 不等于 OpenFHE 的那个变换

`9e1ae3a`:

| Config | GPU CtS Max error | Expected (2⁻⁴⁴) | 超出 |
|---|---|---|---|
| sparse | 1.51e-12 | 5.68e-14 | **26.6×** |
| thormod | 6.45e-10 | 2.91e-11 | **22.2×** |

**`CoeffsToSlots` 独立测试是拿 GPU 对 OpenFHE CPU 比的,它红着,而且参照有 45 bit 分辨率。**

这两件事完全不矛盾:CtS 相对 OpenFHE 偏了,StC 以同样的方式偏回来,复合完美。**这恰好是 §1 那个情形的实例。**

所以:**`477b4df` 不能用来清白 CtS,清白 StC 也只是"相对于 CtS"。**

## 3. 另外两个覆盖缺口

1. **`slots = 1 << 5 = 32`,不是生产的 32768。** log₂(32)=5 个 FFT stage,levelBudget {2,2};生产是 15 个 stage、{3,3}。**塌缩结构完全不同**(`layersCollapse`、`numRotations`、baby/giant step 全都不一样)。
2. **32 < N/2,所以走的是 sparse-encapsulation 分支。** 生产 `Engine.slots = 1 << (log_n−1)` = N/2,`cc.N/2 == slots`,走**dense 分支**。你们测试里那行 `if (slots < GPUcc.N / 2)` 就是这个分支的标记。

**这和 `EvalLinearTransform` 那次是同一类问题:测试是真的、结果是真的,但跑的不是生产那条路。** 我上次没有提前提醒 slot 数,这条责任在我。
